# 0003. spring-kafka напрямую, без Spring Cloud Stream

**Статус:** принято

## Контекст

Сервисы общаются тремя топиками. Нужно выбрать библиотеку: `spring-kafka` или биндеры
Spring Cloud Stream.

## Решение

`spring-kafka`: `KafkaTemplate`, `@KafkaListener`, `DefaultErrorHandler` с
`DeadLetterPublishingRecoverer`.

## Последствия

- Механика видна в коде: `acks=all`, ручной коммит оффсета после возврата из слушателя,
  число попыток и backoff, имя DLT. Всё это можно показать и объяснить.
- Настройки, которые пришлось задать явно, — как раз те, где библиотека молчит:
  суффикс DLT у Spring Kafka по умолчанию `-dlt`, а не `.DLT`, и без явного резолвера
  сообщения молча уезжали не в тот топик.
- Плата: переносимость между брокерами не бесплатна — смена брокера потребует правок кода.

## Альтернативы

- **Spring Cloud Stream.** Слой биндеров ради переносимости, которая здесь не нужна, и
  который прячет ровно ту механику, которая в этом проекте является предметом разговора.
