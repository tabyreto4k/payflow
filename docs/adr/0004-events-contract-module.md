# 0004. Общий модуль `events-contract` вместо копий записей событий

**Статус:** принято

## Контекст

Три события ходят между четырьмя сервисами. Схему нужно где-то зафиксировать так, чтобы
продюсер и потребитель не разошлись молча.

## Решение

Отдельный Gradle-модуль `events-contract`: только `record`-ы событий и константы имён
топиков. Ни Spring, ни логики, ни зависимостей. Единственный модуль, который сервисы делят.

## Последствия

- Рассинхрон полей ловит компилятор, а не прод. Добавление поля в событие — правка в одном
  месте, после которой сборка сама показывает всех, кого это касается.
- Связность направлена в сторону контракта и на этом заканчивается: знание о чужом сервисе
  из модуля не утекает.
- Плата: модуль общий, а значит, изменение контракта требует согласованного релиза. В проде
  это решалось бы версионированием схем и schema registry.

## Альтернативы

- **Копия записей в каждом сервисе.** Честнее для репозиториев, разъехавшихся физически,
  но в монорепо даёт тихий дрейф схем: поле переименовали в одном месте, а узнали об этом
  из DLT.
